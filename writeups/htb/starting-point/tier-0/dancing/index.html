HACK THE BOX · STARTING POINT · TIER 0

03 — Dancing.

Very Easy · Windows · SMB

VERY EASY WINDOWS SMB ENUMERATION ANONYMOUS ACCESS
01 — ENUMERATION

Initial Nmap scan

I started with an Nmap scan to identify exposed ports and determine which Windows services were available on the target. 

nmap -sC -sV <TARGET_IP>

Initial Nmap enumeration of the Windows target.

FINDING 01

Ports 135, 139 and 445 were open.

Port 135 is associated with the Windows RPC endpoint mapper, which helps clients locate available RPC services.

Port 139 exposes SMB through NetBIOS, while port 445 provides direct SMB communication over TCP. The presence of ports 139 and 445 made SMB enumeration the logical next step.

02 — SMB SECURITY

SMB signing configuration

During SMB enumeration, the host reported that message signing was enabled but not required.

SMB security information showing signing enabled but not required.

FINDING 02

SMB signing was enabled but not required.

SMB signing adds integrity protection to SMB communications by attaching a signature to SMB messages. When signing is not required, a client and server may establish an SMB session without signing being mandatory. :contentReference[oaicite:2]{index=2}

This was an important security observation, but it was not the weakness I ultimately used to obtain access. The direct attack path came from being able to authenticate to SMB without a password and enumerate accessible shares.

03 — SMB ENUMERATION

Identifying the SMB host

CrackMapExec identified the host as Windows 10 / Server 2019 Build 17763 x64 and confirmed the target hostname as DANCING. With the SMB service fingerprinted, the next question was whether the server would accept an unauthenticated session. 

crackmapexec smb <TARGET_IP>

CrackMapExec identifying the target operating system and SMB configuration.

FINDING 03

The host identified itself as Windows 10 / Server 2019 Build 17763 x64 with hostname DANCING.

The output also confirmed that SMB signing was not enforced and that SMBv1 was disabled. This provided useful context for the next step: testing whether SMB resources could be accessed anonymously.

04 — SHARE ENUMERATION

Testing anonymous SMB access

I tested the Anonymous account with a blank password and enumerated the available shares together with their permissions. ADMIN$ and C$ were inaccessible from this session, while IPC$ was readable. The important discovery was WorkShares, which provided both read and write access. 

crackmapexec smb <TARGET_IP> -u 'Anonymous' -p '' --shares

Enumerating SMB shares using anonymous authentication.

FINDING 04

Anonymous SMB authentication was accepted, allowing the available shares and their permissions to be enumerated.

The share listing showed several standard Windows administrative shares as well as a custom WorkShares share.

  • ADMIN$ — administrative share; no usable permissions from the anonymous session.
  • C$ — administrative disk share; no usable permissions from the anonymous session.
  • IPC$ — inter-process communication share; readable from the tested session.
  • WorkShares — accessible with read and write permissions.

The custom WorkShares share was the most interesting target because it was accessible anonymously and provided direct access to files.

05 — SMB ACCESS

Accessing WorkShares

With the share identified and accessible through the anonymous session, I connected directly with smbclient to inspect its contents. 

smbclient //<TARGET_IP>/WorkShares -U Anonymous

Connecting to the WorkShares SMB share as Anonymous.

Exploring the share

Once connected, I enumerated the directories and files available through the share and located the flag. 

ls
cd <directory>
ls
get flag.txt

The flag was retrieved directly from the accessible SMB share without requiring a privileged account.

06 — WHAT I LEARNED

Lessons from Dancing

Dancing reinforced the value of service-specific enumeration. Once SMB was identified, understanding the host configuration, authentication options and share permissions was more useful than immediately searching for a software exploit.

The primary weakness was the combination of anonymous SMB access and excessive permissions on the WorkShares share. This allowed an unauthenticated session to reach files that should not have been exposed.

07 — TOOLS & TECHNIQUES

Tools used

The main tools and techniques used during the exercise were:

  • Nmap — port and service enumeration.
  • CrackMapExec — SMB host, authentication and share enumeration.
  • smbclient — direct interaction with the SMB share.
